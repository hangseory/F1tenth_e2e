# (임시) 노트북에서 접속 + RViz 보기

노트북에서 치는 명령만 모았습니다. **그대로 복사해 붙이세요.**

> 제목은 임시입니다. 내용이 굳으면 이름을 바꿉니다.

---

## 0. 먼저 — 둘 다 같은 와이파이에

젯슨과 노트북을 **둘 다 팀 공유기(`yax_5g`)** 에 연결합니다.

> ### ★ 스택을 켠 뒤에는 와이파이를 바꾸지 마세요
> CycloneDDS 가 **기동 시점의 IP 로 네트워크 인터페이스를 고정**하고, 그 뒤
> 재바인딩을 하지 못합니다. 노드는 살아 있는데 **서로 못 듣는 상태**가 되고,
> 조향이 갑자기 먹통이 되는 식이라 하드웨어 고장처럼 보입니다.
> 바꿨다면 반드시 `./race.sh stop` 후 다시 띄우세요.

---

## 1. 젯슨 IP 확인 (SSH 로 들어가서)

```bash
ssh jetson@192.168.50.57
```
비밀번호 `jetsonjetson`

```bash
cd ~/yax && ip -4 -br addr | grep 192.168.50
```

`192.168.50.57` 이 나오면 설정 그대로 쓰면 됩니다. **다른 번호가 나오면** 2번으로.

---

## 2. IP 가 바뀌었을 때만 — 양쪽 다 고쳐야 합니다

젯슨과 노트북 **둘 다** 같은 값이어야 합니다. 한쪽만 고치면 통신이 **0** 입니다.

`<끝자리>` 를 실제 값으로 바꿔서, **젯슨과 노트북 각각에서** 실행:

```bash
cd ~/yax && sed -i 's|^  subnet: .*|  subnet: "192.168.50."|' config/vehicle_car1.yaml && sed -i 's|^    - 192\.168\.[0-9]*\.[0-9]*|    - 192.168.50.<끝자리>|' config/vehicle_car1.yaml && grep -nE 'subnet:|- 192\.168' config/vehicle_car1.yaml | grep -v '#'
```

이 두 값은 **커밋하지 않습니다** (네트워크가 바뀔 때마다 달라지고, 2호차와 공유하는 값이 아닙니다). 그래서 `git pull` 로는 안 들어옵니다.

> 공유기에서 젯슨 MAC 에 **고정 IP 할당**을 걸어두면 이 단계가 아예 없어집니다. 권장합니다.

## 3. 젯슨에서 주행 스택 띄우기 (SSH)

```bash
cd ~/yax && ./race.sh stop && ./race.sh race
```

모드는 상황에 맞게:

| 명령 | 역할 |
|---|---|
| `./race.sh box` | 스택만 기동, **바퀴 안 돎** — 위치추정 확인용 |
| `./race.sh q1` | 라인만 따라 주행 (장애물 회피 없음) |
| `./race.sh race` | 라인 주행 + 장애물 회피 |
| `./race.sh mapping-carto-joy` | Cartographer 맵핑 |

## 4. 노트북에서 RViz — ★ SSH 아니라 **노트북 로컬 터미널**

```bash
cd ~/yax && ./rviz.sh car1
```

`car1` 을 쓰세요. IP 끝자리(`./rviz.sh 57`)도 되지만, IP 가 바뀌면 깨집니다.

### 처음 한 번만 — 노트북 준비물

```bash
sudo apt install ros-humble-desktop ros-humble-rmw-cyclonedds-cpp
```

Jazzy 면 `ros-jazzy-...` 로. RViz·원격 모니터링 용도로만 쓰세요 (실차 빌드 기준은 Humble).

`rviz2` 와 **CycloneDDS 둘 다** 필요합니다. 미들웨어가 한쪽만 다르면 토픽이 **하나도** 안 보입니다.

---

## 5. 성공 판정 — 양쪽에서 이 두 줄이 똑같이 떠야 합니다

```
[dds] ROS_DOMAIN_ID=57  (car1)
[dds] CycloneDDS  |  인터페이스 192.168.50.xx 고정  |  피어 1개
```

| 상태 | 뜻 |
|---|---|
| 양쪽 다 **고정** | ✅ 정상 |
| 양쪽 다 **폴백** | △ 통신은 되지만 `/map` 전달이 자주 실패 |
| **한쪽만 고정** | ❌ **통신 0.** 고정된 쪽은 상대의 멀티캐스트를 못 듣고, 피어 목록에도 상대가 없어 먼저 인사하지도 않습니다 |

`⚠ CycloneDDS 폴백` 은 그 기기의 IP 가 `192.168.50.` 으로 시작하지 않는다는 뜻입니다. 와이파이를 확인하세요.

## 6. RViz 에서 볼 것

| 색 | 무엇 |
|---|---|
| **노란 정육면체** | 차가 지금 **조준하는 점** (회피 오프셋 반영됨) |
| 초록~빨강 선 | 레이싱 라인 (색 = 구간별 목표 속도) |
| 빨간 점들 | 라이다 스캔 |
| 화살표 | 위치추정이 말하는 차의 자세 |

> ### ★ 가장 중요한 확인
> **스캔(빨간 점)이 맵의 벽과 겹쳐 보여야** 합니다. 어긋나 있으면 차는 자기가
> 어디 있는지 모르는 상태입니다.
>
> 어긋났으면 RViz 상단 **`2D Pose Estimate`** 로 실제 위치를 클릭한 채 진행
> 방향으로 드래그합니다.
>
> ⚠ **RViz 클릭은 저장되지 않습니다.** 스택을 끄면 사라집니다. 다음 실행에도
> 쓰려면 젯슨에서 `cd ~/yax && ./race.sh savepose` 를 실행하고, `init_x` 값이
> **실제로 바뀌었는지 눈으로 확인**하세요. 스택이 완전히 뜨기 전에 실행하면
> 조용히 실패합니다.

## 잘 안 될 때

| 증상 | 확인 |
|---|---|
| RViz 창만 뜨고 아무것도 안 보임 | `[dds]` 줄이 양쪽에서 같은가. 와이파이가 같은가 |
| `ros2 topic list` 에 `/parameter_events`·`/rosout` 2개만 | 통신 0. 위 5번 표를 볼 것 |
| `✗ rviz2 가 없습니다` | `sudo apt install ros-humble-rviz2` |
| `✗ 끝자리 N 을 가진 차량 파일이 없습니다` | `config/vehicle_car1.yaml` 의 `peers` 가 실제 IP 와 다름 → 2번 |
| `✗ RViz 설정 없음: config/race.rviz` | `git pull` 로 저장소 최신화 |
| 차가 엉뚱한 데 있다고 나옴 | 스캔과 맵이 겹치는가 → `2D Pose Estimate` → `savepose` |
| 갑자기 조향이 안 먹음 | 스택 켠 뒤 **와이파이를 바꿨는가** → `./race.sh stop` 후 재시작 |
| 토픽이 도는지 모르겠음 | 젯슨에서 `cd ~/yax && ./race.sh check` |
