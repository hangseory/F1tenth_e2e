# 원격 제어판 설계 — 노트북(우분투)에서 차를 제어하고 상태를 본다

2026-11-10. **이 문서만 읽고 구현을 시작할 수 있게** 썼습니다.

원안은 3기 팀(`YAX3_F1T_TEAM2`)의 `MAGP/MAC_GUI_HANDOFF.md` (2026-11-03) 입니다.
그쪽은 맥북 + 자체 `waypoint_nav` 스택 기준이고, 이 문서는 **우분투 노트북 + 우리 `race.sh` 스택** 기준으로 다시 썼습니다. 설계 핵심(서버 주도 UI, SSH 터널, 데드맨)은 그대로 가져왔습니다.

## 1. 왜 만드나

지금 주행하려면 **터미널 3개**가 필요합니다 — 젯슨 SSH 2개(스택·설정) + 노트북 로컬 1개(RViz). 그리고 상태를 보려면 세 화면을 번갈아 봐야 합니다.

구체적으로 2026-11-08~09 에 겪은 것들:

| 겪은 일 | 제어판이 있었다면 |
|---|---|
| 수동 전환 후 `A/B/X/Y` 를 눌러 위치추정이 깨짐 (16회) | 화면 버튼이면 안 눌림 |
| `~/.ros/log/python3_8237_*.log` 를 뒤져 노드를 찾음 | 실행 단위로 탭 + 파일 |
| `subnet`/`peers` 불일치로 RViz 가 안 뜸 | **제어·상태는 DDS 를 안 씀** |
| `cap=0.5` 가 남아 있어 계속 느림 | 현재 값이 화면에 보임 |
| `tune.sh` 로 고친 값이 VS Code 와 충돌 | 에디터를 안 염 |

## 2. 구조 — 서버 주도 UI

```
[노트북 (우분투)]                        [젯슨]
panel_client.py  (PyQt5, ROS 불필요)      panel_server.py  (rclpy, 127.0.0.1:8765)
  서버가 보낸 레이아웃을 그대로 그림  ←──┐   ├─ panel_ui.py : 레이아웃 정의
  위젯 이벤트를 action 으로 전송     ──┤   ├─ 액션 핸들러 : 검증·경고·명령
  서버가 보낸 update 를 위젯에 적용  ←──┤   ├─ ./race.sh 자식 프로세스 관리
  └ ssh -N -L 8765:127.0.0.1:8765 ────┘   └─ 20 Hz 루프, E-STOP, 데드맨
```

**클라이언트는 기능을 하나도 모릅니다.** 버튼 이름·명령·제약·경고 문구·색 규칙이 전부 서버에 있습니다. 클라이언트가 아는 것은 위젯 어휘, 메시지 형식, 키 전송 규칙, 하트비트뿐입니다.

### 이 구조를 고른 이유

**① 젯슨에서 기능이 바뀌어도 클라이언트를 안 고칩니다.**
`race.sh` 에 모드를 하나 추가하면 `panel_ui.py` 만 고치고 서버를 재시작합니다. 노트북은 다시 접속해 새 레이아웃을 받습니다. 클라이언트를 고쳐야 하는 건 **위젯 어휘나 메시지 형식이 바뀔 때뿐**이고, 그때는 `PROTOCOL` 번호를 올립니다. 버전이 다르면 클라이언트는 "업데이트 필요" 화면만 띄웁니다.

**② 노트북에 ROS 가 필요 없습니다 — 이게 제일 큽니다.**
제어와 상태는 SSH 터널로만 오갑니다. `ROS_DOMAIN_ID`·`subnet`·`peers`·멀티캐스트가 **관여하지 않습니다.**

> 2026-11-08~09 에 이 설정들 때문에 RViz 가 하루 종일 안 떴습니다. `subnet` 이 한쪽만 `192.168.1.` 이어서 한쪽은 고정, 한쪽은 폴백 → 통신 0. SSH 는 그동안에도 **멀쩡히 됐습니다.** 제어 경로를 SSH 에 두면 그 실패 모드가 사라집니다.

**③ 서버가 상태와 프로세스를 소유합니다.**
노트북이 끊기거나 뚜껑을 닫아도 **젯슨 노드는 안 죽습니다.** 다시 접속하면 현재 상태를 받습니다.

**④ 표준 라이브러리만 씁니다.**
줄 단위 JSON over TCP(NDJSON). 젯슨에 `websockets`·`fastapi` 가 없고 대회장에서 pip 를 못 쓸 수 있습니다. 서버는 `socketserver`+스레드, 클라이언트는 `QTcpSocket`.

**⑤ 보안은 SSH 에 맡깁니다.**
서버는 `127.0.0.1` 에만 bind 합니다. 외부에서 직접 못 붙습니다.

### 원안과 달라진 점 (우분투 노트북)

| | 원안 (맥북) | 우리 |
|---|---|---|
| 클라이언트 툴킷 | PyQt6 + PyQt5 shim | **PyQt5 하나** — 양쪽 다 apt 로 이미 있음 |
| 클라이언트 실행 위치 | 맥 전용 | **같은 파일을 젯슨에서도** 실행 가능 (모니터 연결 시) |
| 대상 스택 | `waypoint_nav` 노드를 하나씩 | **`race.sh` 모드 단위** |
| 설정 변경 | 직접 yaml | **`tune.sh` 경유** (백업·검증·되돌리기가 이미 있음) |

## 4. 안전 — 가장 중요한 절

> ### ★ 무선 E-STOP 은 그 자체로 안전장치가 아닙니다
> 와이파이가 끊기면 **정지 명령도 안 갑니다.** 그래서 반대로 설계합니다 —
> **끊기면 서버가 알아서 멈춥니다.**

### 데드맨 (하트비트)

1. 클라이언트는 연결된 동안 **10 Hz 로 `heartbeat`** 를 보냅니다.
2. **수동 모드**에서 하트비트가 **0.3초** 끊기면 서버가 즉시 정지합니다 (`/teleop` 에 속도 0).
3. **자율주행 중** 끊김은 서버 설정 `on_disconnect` 로 정합니다:
   - `stop` (기본, 연습용) — 멈춘다
   - `keep` (레이스용) — 그대로 달린다
   현재 값은 상태 줄에 항상 표시합니다.

### 최종 안전장치는 여전히 조이스틱

| 수단 | 경로 | 성격 |
|---|---|---|
| **조이스틱 `LB`** | 2.4 GHz 직결 → 젯슨 | **최종 안전장치.** 와이파이와 무관 |
| 제어판 E-STOP | 노트북 → SSH → 서버 → `/teleop` | 보조. 와이파이에 의존 |
| 데드맨 | 서버 자체 판단 | 연결이 끊겼을 때의 보험 |

**차 옆에는 항상 조이스틱을 든 사람이 있어야 합니다.** 제어판은 그 사람을 대체하지 않습니다.

### 조이스틱 프리셋 잠금은 유지

2026-11-09 에 수동 모드의 `A/B/X/Y` 프리셋을 전부 잠갔습니다 (`[999,999,999]`). 자율 출발 버튼(`B`)과 같은 버튼이라, 수동 전환 뒤 누르면 위치가 순간이동합니다. **제어판이 생겨도 이 잠금은 풀지 않습니다.**


### 서버가 강제하는 제약 (클라이언트는 모름)

- **모드 실행 중에는 맵/웨이포인트/위치추정을 못 바꿉니다.** launch 시점에만 읽히므로, 바꿔도 안 먹는데 바뀐 것처럼 보이면 안 됩니다. 바꾸려면 정지 먼저.
- **웨이포인트 파일이 없으면 시작을 거부**하고 이유를 띄웁니다. 2026-11-09 에 `1109-2_clean_wp` 로 적었는데 실제 파일은 `..._map_wp.csv` 라 launch 가 죽었습니다.
- **`mode: cartographer` 인데 `.pbstream` 이 없으면 거부**합니다. `_clean` 을 벗긴 원본 이름까지 찾아보고 없으면 재측량을 안내합니다.
- **`cap` 이 0 이 아니면 상태 줄에 항상 표시**합니다. 저속 시험용으로 걸어둔 걸 잊어 "왜 느리지" 로 헤맨 적이 있습니다.
- **`cap` 을 0.5 이하로 내리려 하면 경고**합니다. 2100 erpm 은 센서리스 BLDC 가 가장 불안정한 구간입니다 (실측: 지령 500~1000 erpm 에서 전류 30~50 A 를 먹고 거의 안 돎). 저속 시험은 **1.0 m/s 이상**으로.

## 7. 구현 단계

### 1단계 — 뼈대 (반나절). 기존 코드를 안 건드린다

- `panel_server.py`: `socketserver` + 스레드, `127.0.0.1:8765`
- `./race.sh <모드>` 를 자식 프로세스로 띄우고 stdout/stderr 를 `log` 로 중계
- 로그를 `logs/<패널시작시각>/<프로그램>.log` 로도 복사
- 하트비트 + 데드맨 (수동 0.3 s → 정지)
- `panel_client.py`: 레이아웃 받아 그리고, 이벤트 보내고, 로그 탭 표시
- 레이아웃은 **실행 + 로그 + E-STOP** 만

이것만으로 터미널 3개가 1개로 줄고, 로그가 한곳에 모입니다.

### 2단계 — 설정
맵/웨이포인트 드롭다운(파일 스캔), 위치추정 모드, `tune.sh` 연동(`cap`·`q1`), 5절의 제약 검증

### 3단계 — 상태
`rclpy` 구독: `/sensors/core`(배터리·erpm), `/amcl_pose`, `localization_monitor` 잔차, `race.sh check` 요약, DDS 상태

### 4단계 — 편집기
맵 편집(벽 지우기/그리기) · 웨이포인트 편집. 3기 팀의 `map_editor.py`(25 KB) / `waypoint_editor.py`(34 KB) 를 참고. **우리에게 없는 기능입니다** — 지금은 재생성만 가능합니다.

## 8. 쓰는 법 (구현 후)

```bash
# 노트북 — 터널 (한 번)
ssh -N -L 8765:127.0.0.1:8765 jetson@192.168.50.57 &

# 젯슨 — 서버
cd ~/yax && ./panel.sh --server

# 노트북 — 제어판
cd ~/yax && ./panel.sh
```

RViz 는 **따로** 띄웁니다. 맵·스캔은 데이터가 무거워 터널에 안 맞습니다:

```bash
cd ~/yax && ./rviz.sh car1
```

| | 경로 | DDS |
|---|---|---|
| 제어판 (모드·설정·상태·로그) | SSH 터널 | **불필요** |
| RViz (맵·스캔·라인) | DDS | 필요 |

제어판이 되는데 RViz 가 안 뜨면 **네트워크 설정 문제**로 범위가 좁혀집니다. 지금은 그 둘이 같이 죽어서 원인 구분이 안 됩니다.

## 9. 안 할 것

- **클라이언트에 기능 로직을 두지 않습니다.** 버튼 이름 하나라도 서버에서 받습니다. 그래야 젯슨만 고치면 됩니다.
- **제어판을 최종 안전장치로 쓰지 않습니다.** 조이스틱 `LB` 가 그 역할입니다.
- **`race.sh`/`tune.sh` 를 우회해 직접 yaml 을 쓰지 않습니다.** `tune.sh` 에 백업·검증·`--undo` 가 이미 있습니다.
- **42 KB 짜리 원본 `control_panel.py` 를 복사하지 않습니다.** 경로가 `~/MAGP/MAGP` 로 박혀 있고 노드를 하나씩 켜는 구조라 우리와 안 맞습니다. 가져올 것은 **구성과 안전 설계**입니다.
