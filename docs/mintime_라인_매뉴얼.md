# 최소시간 라인 (`./race.sh mintime`) 매뉴얼

경로 모양과 속도를 **한 번에** 최적화해 랩타임이 가장 짧은 라인을 만듭니다.
기존 `line` / `waypoints-kappa` 는 "곡률을 줄인 경로를 먼저 만들고 속도를 나중에
붙이는" 방식이라 랩타임을 직접 줄이지 않습니다.

> **급하면:** [한 장 요약](#한-장-요약) 만 보세요.
> **옵션별 의미·권장값·영향 표:** `docs/웨이포인트_가이드.md`

---

## 0. 처음 한 번 — CasADi 설치

```bash
pip install --user --no-deps casadi
python3 -c "import casadi, numpy; print(casadi.__version__, numpy.__version__)"   # numpy 1.26.4 여야 함
```

⚠ **`--no-deps` 를 꼭 붙이세요.** 안 붙이면 numpy 를 2.x 로 올려 cv2·matplotlib·colcon 이 깨집니다.

## 1. 만들기 — 세 가지 방법

> **처음이면 `./race.sh mintime` (인자 없이)** — 맵 선택부터 값까지 하나씩 묻고, Enter 는 기본값입니다.
> 자세한 흐름은 `docs/웨이포인트_가이드.md` 0절.

### ① 지도에 클릭으로 경로 찍기 (권장, 화면 필요)

```bash
cd ~/yax && ./race.sh mintime c11_clean --sketch --out c11_clean_wp_mt1
```

| 조작 | 동작 |
|---|---|
| 좌클릭 | 점 추가 |
| 우클릭 / `z` | 마지막 점 취소 |
| Enter | 완료 (4점 이상) → 최적화(2초 정도) → 결과 창 |
| Esc | 취소 |

- **첫 점(★)이 출발점**이고, **찍는 순서가 주행 방향**입니다 (노란 화살표로 표시).
- **대충 찍어도 됩니다.** 코너마다 2~3점, 직선은 양 끝만 찍으면 되고 10~20점이면
  충분합니다. 최적화가 찍은 선에서 좌우 ±1 m 안에서 모양을 새로 정하므로, 여기서
  정하는 건 **어느 틈으로 지나갈지** 뿐입니다.
- 벽에서 0.2 m 안으로 붙은 구간은 보라색으로 표시됩니다. 거기는 조금 떨어지게 찍으세요.
- 기존 라인을 참고용으로 깔아 두려면 `--like <라인>` 을 같이 주세요.
- 툴바의 확대/이동 모드에서 클릭한 건 점으로 찍히지 않습니다.

찍은 점은 `maps/<맵>/sketch_<출력이름>.csv` 에 저장됩니다. **`waypoints/` 가 아닌 이유:**
듬성듬성한 점이라 주행 라인으로 쓰면 안 되는데, `waypoints/` 에 있으면 `./race.sh wp` 목록에 뜹니다.

### ② 기존 라인을 기준으로

```bash
cd ~/yax && ./race.sh mintime c11_clean --like c11_clean_wp_kappa_pre --out c11_clean_wp_mt2
```
`waypoints-kappa` 로 만든 라인, `./race.sh log` 로 녹화한 라인, 편집기로 고친 라인 등
무엇이든 됩니다. 화면 없이 젯슨에서도 됩니다.

### ③ 저장된 스케치로 설정만 바꿔 다시

```bash
cd ~/yax && ./race.sh mintime c11_clean \
    --sketch-file src/race_stack/maps/c11_clean/sketch_c11_clean_wp_mt1.csv \
    --out c11_clean_wp_mt1_su80 --steer-util 0.80
```

### (참고) 기준선 없이 — 자동 중심선

`--sketch` / `--like` 를 둘 다 빼면 지도에서 중심선을 자동으로 뽑습니다.
**양쪽이 벽으로 막힌 복도형 트랙**에서만 쓰세요. c11 처럼 넓은 방에 섬이 있는 지도에서는
엉뚱한 틈을 골라 라인이 꼬였습니다.

## 3. 패스 (`--passes`) — 1 과 3 은 경로 자체가 다릅니다

최적화는 기준선 좌우 ±`--w-max`(기본 1 m) 안에서만 움직입니다. `--passes N` 은
결과를 새 기준선으로 삼아 N 번 다시 풉니다. 그때마다 범위가 최대 1 m 씩 옮겨갑니다.

c11, 같은 스케치 16점 (1호차 값, η 0.8, **명목 조향 기준이던 2026-11-11 오전 수치**):

| | 길이 | 예상 랩 | 벽까지 최소 |
|---|---|---|---|
| 1패스 `c11_clean_wp_mintime` (kappa_pre 기준) | 18.92 m | 6.41 s | 0.37 m |
| 1패스 (스케치 기준) | 19.27 m | 6.63 s | 0.36 m |
| **3패스 `c11_clean_wp_mintime_p3`** | **13.77 m** | **4.78 s** | **0.25 m** |

3패스는 방 전체를 크게 도는 대신 **C자 섬에 바짝 붙어 도는 작은 원**이 됩니다.
지도상으로는 벽에 안 걸려서 합법이지만, **스케치한 경로를 벗어난 것**입니다.

- **기본값은 1패스입니다.** 스케치한 경로를 지킵니다.
- 3패스는 **트랙 경계(콘·테이프 등)가 지도에 전부 벽으로 그려져 있을 때만** 쓰세요.
  안 그려진 경계는 최적화가 모릅니다. 맵 편집기로 벽을 먼저 그리면 됩니다
  (`카토그래퍼_ver_매뉴얼.md` 3절 "맵 편집기").
- 패스가 앞 패스보다 나빠지면 거기서 멈추고 가장 좋은 결과를 씁니다
  (이름의 `_p3` 은 **요청한** 패스 수입니다).

## 4. 주요 옵션

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `--car car1\|car2` | `.car` 의 차 | 어느 차 값으로 만들지. **그 라인을 달릴 차**로 맞추세요 |
| `--safety` | 0.25 m | 벽과 차 중심 사이 최소 거리 (차 반폭 0.15 + 여유 0.10) |
| `--steer-util` | 0.70 | 라인이 쓸 수 있는 조향 비율. 나머지 30% 는 오차 보정용. **기준은 실측 유효 조향**(아래 4-1) |
| `--ref-smooth` | 0.0005 | 기준선 평활. 이미지·손으로 찍은 점처럼 거칠면 **0.003~0.01**. 최적화가 실패하면 이것부터 |
| `--dkappa-max` | 1.5 | 곡률이 바뀌는 속도 상한 [1/m²]. 작을수록 따라가기 쉽고 느림 |
| `--w-max` | 1.0 m | 기준선에서 좌우로 움직일 수 있는 폭 |
| `--passes` | 1 | 위 3절 |
| `--grip` | race 모드 값 | grip_util 직접 지정 |

### 4-1. ★ 조향 한계는 실측값을 씁니다 — `geometry.steer_eff_max`

명목 `max_steer` 는 서보 리밋에서 **계산한** 명령 한계일 뿐, 바퀴가 실제로 그만큼 꺾이지
않습니다. 1호차 2026-11-11 주행 로그(조향 한계에 붙은 34구간, 궤적에 원 맞춤):

| | 명목 (서보 계산) | **실측** |
|---|---|---|
| 최대 조향 | 27.5° | **21.2°** (좌 21.0° / 우 21.5°) |
| 최소 반경 | 0.634 m | **0.85 m** |

명령은 27.5° 까지 나갔고(소프트웨어 제한 아님) 횡가속은 0.26 g 뿐이라 **바퀴가 덜 꺾인 것**입니다
(게인 과대 ~8% + 풀락에서 서보세이버·링키지가 밀림으로 추정 — 차를 들어 올려 직접 재서 확정할 것).

이 값을 `config/vehicle_car1.yaml` 의 `geometry.steer_eff_max: 0.370` 에 적어 두었고,
**mintime 생성기와 `./race.sh wp` 판정이 이 값을 기준으로** 씁니다 (컨트롤러는 안 읽음).
기동 로그에 `[vehicle] 실측 유효 조향 ±21.2° ...` 줄이 뜹니다. 없는 차(2호차)는 명목값을 쓰고 경고합니다.

다시 재려면 (서보·링키지를 손본 뒤 등):
```bash
./race.sh steer-meas --car car1            # 그 차 조향 설정의 로그만 골라서 잼
./race.sh steer-meas 20261111 --car car1   # 이름 조각으로 로그 제한
```
결과의 `★ 권장 geometry.steer_eff_max` 를 vehicle yaml 에 넣으면 됩니다.
⚠ 로그에는 어느 차인지 안 남아서, **그 차의 명목 max_steer 와 조향 최대값이 맞는 로그만** 씁니다.
⚠ 1.2~1.6 ㎧ 에서 잰 값입니다. 더 빠를 때는 덜 돌 수 있습니다.

> **2026-11-11 이전 문서·라인의 "추종조향 %" 와 `--steer-util` 은 명목 기준이었습니다.**
> 명목 0.70 은 실측으로 **약 90%** 라 여유가 10% 뿐이었습니다. 지금 기본 0.70 은 실측 기준 30% 입니다.

### 4-2. 조향 여유 (`--steer-util`) — 30% 를 남기는 이유

컨트롤러는 라인에서 벗어나면 조향을 **더** 꺾어 돌아옵니다. 라인 자체가 조향을 100%
쓰게 만들면 더 꺾을 수가 없어 바깥으로 벌어집니다. kappa_pre 라인에서 랩의 16~20% 가
조향 포화였고 추종 오차가 8.5 → 18 cm 로 커진 게 이것입니다. 남긴 30% 는 타이어 슬립,
위치 추정 오차, 명령 지연을 메우는 데 씁니다.

대회 B코스(1.8 m 폭)에서는 실측 30% 여유(기본 0.70)를 지켜도 랩 손해가 거의 없습니다
(명목 기준 대비 +0.02 s). **좁은 틈이 있는 트랙은 다릅니다** — c11 은 섬과 벽 사이 S자 틈에서
반경 1.25 m 이상으로는 못 돌아 0.70 이 **해가 없고**, 0.75 는 큰 우회로(7.96 s), **0.80 이면 6.57 s** 입니다.
이때 생성기는 상한을 단계적으로 조여 보다가 막히는 곳에서 `✗ κ≤... 에서 해가 없음` 을 띄웁니다.

**정리:** 기본 0.70 으로 먼저 → 해가 없으면 0.75 → 0.80 (실측 여유 20%, 대신 천천히 확인).
0.80 보다 올리면 추종 오차를 보정할 조향이 거의 안 남습니다.

## 5. 비교 — `--eval` / 사진 — `wp-show`

```bash
cd ~/yax && ./race.sh mintime c11_clean --eval --car car1
```

이 맵의 모든 라인을 **컨트롤러와 같은 물리**로 비교합니다.

```
  이름                         예상랩 (매끈)  길이   v범위     추종조향max  p95  >80%  dκ/ds p99  벽min
  c11_clean_wp_mintime          6.41  6.20  18.92  2.07~4.28     76%    70%  0.0%     1.50   0.371
✗ c11_clean_wp_kappa_pre        8.54  8.36  21.11  1.51~3.94    141%   105% 15.5%     4.25   0.500
```

| 칸 | 뜻 |
|---|---|
| 예상랩 | map_controller 와 같은 곡률·속도 계산. **지연·추종오차가 없으니 하한**입니다 (kappa_pre 예상 8.5 s → 실측 약 12 s) |
| (매끈) | 점 노이즈를 걷어낸 곡률로 본 랩. 예상랩과 차이가 크면 CSV 점이 거칠어 컨트롤러가 쓸데없이 감속하는 것 |
| 추종조향max | 라인을 따라가기만 할 때 쓰는 조향 / 최대 조향. **80% 넘으면 ⚠, 100% 넘으면 ✗(못 돈다)** |
| >80% | 조향을 80% 넘게 쓰는 구간 비율 |
| 벽min | 라인에서 가장 가까운 벽까지 [m]. 차 반폭(0.15) 보다 충분히 커야 합니다 |

`./race.sh wp` 와 숫자가 다를 수 있습니다. `wp` 는 이웃한 세 점으로, `--eval` 은
±0.15 m 떨어진 세 점으로 곡률을 재기 때문입니다. 또 `wp` 는 **이 기기의 `.car`** 기준이라,
노트북(car2)에서 1호차 라인을 보면 `✗못돈다` 로 뜰 수 있습니다 — 1호차 기준은 `--eval --car car1`.

사진(속도색 오버레이)은:
```bash
./race.sh wp-show                 # 지금 맵 라인 목록 → 번호(1 3 / 2-5)로 골라 열기
./race.sh wp-show comp26          # 이름 조각
```
노트북에서도 됩니다 — `wp`·`wp-show`·`mintime`·`steer-meas` 는 ROS·차 없이 돕니다.

## 7. 동작 원리 (요약)

곡선 좌표계 최소시간 최적제어(OCP), CasADi + IPOPT. TUM `opt_mintime`
(Christ et al. 2021) 계열이고 차량 모델·제약을 우리 컨트롤러에 맞췄습니다.

```
상태  n(기준선에서 옆 오프셋)  ξ(진행각 오차)  u=v²
입력  κ(차의 곡률)  a⁺/a⁻(가속/제동)
목표  Σ 구간시간 + 작은 벌점·(dκ/ds)²
제약  (a⁺/a_acc)² + (a⁻/a_brk)² + (v²κ/a_g)² ≤ 1     ← speed_profile.py 와 같은 마찰원
      |κ| ≤ tan(steer_util·steer_eff_max)/L             ← 조향 여유 (실측 한계 기준)
      |dκ/ds| ≤ dkappa_max                              ← 컨트롤러가 따라갈 수 있게
      −w_오른쪽 ≤ n ≤ w_왼쪽,  1 − n·κ_ref ≥ 0.3        ← 벽, 라인 꼬임 방지
      v ≥ min_speed
```

`a_g = grip_util·μ·pac_d·g`, 가속·제동 한계, `max_steer`, `min_speed` 는 **race_script.yaml +
차량 파일에서 컨트롤러가 실제로 쓰는 값**을 읽습니다.

순서: 기준선 0.1 m 재샘플 → 법선 방향으로 벽(점유 픽셀 + `maps/<맵>/outer·inner_bound.npy`)까지 폭 측정
→ 매끈한 문제로 워밍업 → 본 최적화 → **실제 최근접 벽거리 재검사, 어긴 곳만 좁혀 재최적화**(최대 6회)
→ 0.05 m 재샘플 → 컨트롤러 모델로 재평가 → 저장.

**모델에 없는 것:** 구동 지연, 추종 오차, 차의 동역학(질점 취급). 그래서 예상 랩은 하한이고,
조향 30% 여유와 곡률 변화율 제한이 그 차이를 흡수합니다.

참고: Christ et al. VSD 2021 / Heilmeier et al. VSD 2019 / ForzaETH race_stack (arXiv 2403.11784) /
arXiv 2602.15642 (주행 로그로 구간별 한계를 갱신하는 적응 루프 — 아직 미구현)

## 8. 예 — 대회 B코스 (`comp26_B`)

대회 예시 이미지(체육관 31.2×19.5 m)에서 B코스(우회전)를 뽑아 맵으로 만든 것입니다.
축척 32.55 px/m, 폭 1.84 m(규정 1.8), 흰 중앙선 65.5 m(주회 64.5). 중앙선은
`maps/comp26_B/sketch_centerline.csv`. **그림에서 만든 맵이라 실제와 수십 cm 다를 수 있으니
당일 SLAM 맵으로 다시 만드세요.**

```bash
./race.sh mintime comp26_B --car car1 --sketch-file src/race_stack/maps/comp26_B/sketch_centerline.csv \
    --ref-smooth 0.01 --safety 0.35 --out comp26_B_wp_mintime_s35
```

| safety | 파일 | 예상 랩 | 벽min |
|---|---|---|---|
