# 웨이포인트 가이드 — 라인 생성 옵션 정리

`./race.sh mintime` 으로 라인을 만들 때 조정하는 값들의 **의미 / 기본·권장값 / 바꿨을 때 영향**.
사용법 전체는 `docs/mintime_라인_매뉴얼.md` 를 보세요.

수치는 2026-11-11 c11, 대회 B코스(`comp26_B`), 1호차로 직접 돌려본 결과입니다.

## 0. 가장 쉬운 방법 — 대화형

```bash
./race.sh mintime
```

인자 없이 실행하면 하나씩 묻습니다. **Enter 를 치면 `[ ]` 안의 기본값**을 씁니다.

1. 맵 — 목록에 `★지금`(race_script 의 맵), 라인·스케치 개수 표시
2. 할 일 — 라인 만들기 / 이 맵의 라인 비교만
3. 차 — 기본은 이 기기의 `.car`
4. 기준선 — 클릭 / 저장된 스케치 / 기존 라인 / 자동 중심선
5. 프리셋 — **안전 / 기본 / 공격** (아래 5절 표). 고른 프리셋 값이 다음 질문들의 기본값이 됨
6. 값 — `safety`, `steer-util`, `dkappa-max`, `grip`, `ref-smooth`, `w-max`, `passes`, 출력 이름
   (각 뜻은 아래 1~3절)

끝나면 **같은 설정을 다시 만드는 명령 한 줄**을 찍어 줍니다. 이걸 복사해 두면 나중에 그대로 재현됩니다.

## 1. 자주 만지는 값

| 옵션 | 의미 | 기본 / 권장 | 바꿨을 때 영향 (실측) |
|---|---|---|---|
| `--safety` | 라인(차 중심)과 가장 가까운 벽 사이 최소 거리 [m]. 차 반폭 0.15 + 여유 | 0.25 / **처음 0.35**, 익숙해지면 0.25 | ↑ 벽에서 멀어져 안전, 라인이 길어짐. B코스: 0.25→0.35는 +0.1 s, 0.50은 +0.6 s. 너무 키우면 좁은 곳이 막혀 해가 없음 |
| `--steer-util` | 라인이 쓸 수 있는 조향 비율. **실측 한계(1호차 21.2°) 기준**. 나머지는 추종 보정·슬립용 | 0.70 / 일반 0.70~0.80, 공격 0.85 | ↑ 더 급한 코너를 허용해 약간 빨라짐(B코스 0.70→0.85: −0.1 s). 대신 보정 여유가 줄어 급한 코너에서 조향이 한계에 붙고 바깥으로 벌어짐. ↓ c11은 0.70이면 해가 없고 0.75는 우회로, 0.80에서 6.57 s |
| `--dkappa-max` | 곡률이 바뀌는 속도 상한 [1/m²]. 직선에서 코너로 얼마나 급하게 들어가는지 | 1.5 / 안전 1.0, 공격 2.0 | ↓ 코너 진입이 부드러워져 컨트롤러가 따라가기 쉬움, 약간 느려짐. 너무 작으면 헤어핀에서 해가 없음. ↑ 차이 작음 |
| `--grip` | 라인을 설계하고 **CSV 속도 상한**을 적을 때 쓰는 grip_util(η) | 지금 race 값(1호차 0.8) / 안전 0.8, 공격 1.0 | 라인 모양은 거의 안 바뀜. **CSV 속도는 상한으로만 쓰이므로**, 낮게 적으면 컨트롤러 η 를 올려도 그 이상 안 빨라지고, 높게 적으면 η 를 올리는 만큼 빨라짐 (공격 라인: η 0.8 14.66 s → 1.0 13.29 s) |
| `--car` | 어느 차 값으로 만들지 | `.car` 의 차 / **달릴 차** | 조향 한계·마찰·축간거리가 전부 바뀜. 다른 차 값으로 만들면 못 도는 라인이 나올 수 있음 |

### 조향 여유(`--steer-util`)를 왜 30% 나 두나

여유는 **21° 측정 오차용이 아니라 컨트롤러가 따라가면서 쓰는 추가 조향**용입니다. 11/11 로그에서
"명령 조향 − 라인 곡률이 요구하는 조향" 을 재보니, **잘 따라갈 때(추종 오차 5 cm 미만)도 p90 5.5°,
p95 8.4°(실측 한계의 40%)** 를 더 썼습니다. 여유 10% 면 2.1° 뿐이라 급한 코너에서 바로 포화됩니다.
(원래 못 도는 라인으로 달린 로그라 과대일 수 있음 — 새 라인으로 달린 뒤 다시 재볼 것)

| 용도 | 실측 대비 여유 | `--steer-util` |
|---|---|---|
| 처음 / 안전 | 30~35% | 0.65~0.70 |
| 일반 | 20% | 0.80 |
| 공격 | 15% | 0.85 |
| 10% | 시도는 가능 | 0.90 — 급한 코너에서 포화 각오 |

## 2. 기준선(경로) 관련

| 옵션 | 의미 | 기본 / 권장 | 바꿨을 때 영향 |
|---|---|---|---|
| `--sketch` / `--like` / `--sketch-file` | 기준선을 어떻게 줄지: 클릭 / 기존 라인 / 저장된 스케치. **어느 틈으로 지나갈지, 주행 방향, 출발점**을 정함 | — / 클릭 스케치 10~20점 | 결과 경로의 위상이 여기서 정해짐. 없으면 자동 중심선(복도형 트랙에서만 쓸 만함) |
| `--w-max` | 기준선에서 좌우로 움직일 수 있는 최대 폭 [m] | 1.0 / 1.0 | ↑ 더 좋은 라인을 찾을 여지가 생기지만, 넓은 방 맵에서는 스케치한 경로를 벗어날 수 있음 |
| `--ref-smooth` | 기준선을 매끄럽게 하는 정도 | 0.0005 / **이미지·손 스케치면 0.003~0.01** | ↑ 기준선 노이즈 때문에 생기는 최적화 실패가 사라짐 (B코스: 0.0005 실패 → 0.01 성공). 너무 크면 기준선이 실제 경로에서 벗어남 |
| `--passes` | 결과를 새 기준선으로 다시 푸는 횟수. 2 이상이면 이름에 `_pN` 이 붙음 | 1 / 1 | ↑ 매번 최대 `w_max` 씩 경로가 옮겨감. c11은 3패스에서 19 m → 13.8 m(섬에 붙는 작은 원). **트랙 경계가 지도에 다 그려져 있을 때만** 쓸 것 |

## 3. 거의 안 만지는 값

| 옵션 | 의미 | 기본 | 영향 |
|---|---|---|---|
| `--step` | 최적화 격자 간격 [m] | 0.10 | ↓ 정밀해지지만 느려짐. 결과 CSV 는 항상 0.05 m 간격 |
| `--w-dk` | 곡률 변화 매끄러움 가중치 | 0.02 | ↑ 매끄럽고 약간 느림 |
| `--v-max` | 속도 상한 [m/s] | 7.0 | 그립이 먼저 걸려서 보통 영향 없음 |
| `--mode` | grip_util 을 어느 모드 값에서 읽을지 | race | `--grip` 으로 직접 주는 게 편함 |
| `--out` / `--force` | 출력 이름 / 덮어쓰기 | `<맵>_wp_mintime` | 같은 이름이 있으면 `--force` 없이는 멈춤 |

## 4. 옵션이 아니라 차량 파일에서 읽는 값

`config/vehicle_<차>.yaml` 과 `race_script.yaml` 의 값을 **컨트롤러와 똑같이** 씁니다.

| 값 | 1호차 | 영향 |
|---|---|---|
| `geometry.steer_eff_max` (실측 조향 한계) | 0.370 rad (21.2°) | `--steer-util` 의 기준. `./race.sh steer-meas --car car1` 로 다시 잴 수 있음 |
| `mu × pac_d` (실효 마찰) | 0.724 | 코너 속도 → 라인 모양 |
| `grip_util.race` (η) | 0.8 | 마찰을 어디까지 쓸지 |
| `a_lon_brk` (제동 한계) | 2.4 m/s² | 코너 진입 전 감속 거리 → 코너를 언제 꺾기 시작할지 |
| `min_speed` | 1.4 m/s | 가장 느린 코너 속도의 바닥 |
| `wheelbase`, `lf` / `lr` | 0.33 m 등 | 조향각↔반경 환산, 가속 한계 |

> 명목 `max_steer`(27.5°)는 서보 리밋에서 **계산한 명령 한계**라 라인 판단에 쓰지 않습니다.
> 1호차는 실제로 21.2° 만 꺾입니다 (2026-11-11 로그 34구간). 실측값이 없는 차는 명목값을 쓰고 경고합니다.

## 5. 지금 쓰는 조합 (1호차, 대회 B코스)

| 버전 | safety | steer-util | dkappa-max | grip | 예상 랩 (η 0.8) |
|---|---|---|---|---|---|
| 안전 `comp26_B_wp_safe` | 0.40 | 0.65 | 1.0 | 0.8 | 15.59 s |
| 기본 `comp26_B_wp_mintime_s35` | 0.35 | 0.70 | 1.5 | 0.8 | 14.86 s |
| 공격 `comp26_B_wp_aggro` | 0.22 | 0.85 | 2.0 | 1.0 | 14.66 s (η 1.0 이면 13.29 s) |

이미지나 손으로 찍은 기준선이면 세 버전 모두 `--ref-smooth 0.01` 을 같이 줍니다.

```bash
# 안전
./race.sh mintime comp26_B --car car1 --sketch-file src/race_stack/maps/comp26_B/sketch_centerline.csv \
    --ref-smooth 0.01 --safety 0.40 --steer-util 0.65 --dkappa-max 1.0 --out comp26_B_wp_safe
# 공격
./race.sh mintime comp26_B --car car1 --sketch-file src/race_stack/maps/comp26_B/sketch_centerline.csv \
    --ref-smooth 0.01 --safety 0.22 --steer-util 0.85 --dkappa-max 2.0 --grip 1.0 --out comp26_B_wp_aggro
```

**달리는 순서:** 안전 → 기본 → 공격(추종이 깨끗할 때, η 를 올려가며).
예상 랩은 지연·추종 오차가 빠진 **하한**입니다.

## 6. 막혔을 때

| 증상 | 먼저 할 것 |
|---|---|
| `✗ 최적화 실패` | `--ref-smooth` 를 0.003 → 0.01 로 |
| `✗ κ≤... 에서 해가 없음` | 그 곡률 상한으로는 못 도는 통로 → `--steer-util` 을 0.75 → 0.80 으로, 또는 `--safety` 를 낮춤 |
| `통로 폭이 0` 경고 | 기준선이 벽에 붙음 → 스케치를 벽에서 떨어지게 다시, 또는 `--safety` 낮춤 |
| `./race.sh wp` 에서 `✗못돈다` | 이 기기의 `.car` 가 다른 차일 수 있음 → `./race.sh mintime <맵> --eval --car car1` 로 확인 |
